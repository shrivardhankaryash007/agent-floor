Tier T0: fresh `HOME` under `~/.af-dry` (outside `/tmp`, so `/tmp` allowances cannot mask anything), a local `git clone` of main at `4c0a330`, no vendor login, no real secret. macOS 26.6.2, Apple silicon, srt 0.0.79. The CLIs were the owner's installed ones (claude 2.1.98, codex 0.159.3, agy 1.3.5) but with the fresh HOME they had no credentials.

Not verified here (needs a logged-in account, which this tier forbids): that the OAuth login and model calls work through the generated host list. The hosts `platform.claude.com`, `console.anthropic.com`, `*.googleapis.com`, `accounts.google.com`, `auth.openai.com`, `chatgpt.com` and `api.openai.com` are best knowledge, not receipts. Also not run: interactive Codex and agy sessions, and WebFetch (see the last section of `INSTALL-FOR-AGENTS.md`).

Friction found: `agent-floor` is not on PATH after `uv sync` alone, so the guide installs it with `uv tool install --editable .`.

## What is missing for Linux (untested; no Linux host was used)

| Gap | Detail |
|---|---|
| srt on Linux | srt uses bubblewrap and socat plus ripgrep instead of Seatbelt; `init` does not check for them, and `doctor` would only report a failing srt |
| macOS-only policy flags | `weaker_network_isolation` (trustd) and the Seatbelt PTY behaviour behind `allow_pty` have no Linux meaning; `init` still sets them |
| macOS paths in built-ins | `~/Library/LaunchAgents`, `~/Library/Mobile Documents`, `~/Library/CloudStorage`, `/private/tmp` are hard-coded; Linux equivalents (`~/.config/autostart`, systemd user units, `~/.config/systemd`) are not protected |
| Vendor behaviour | S1 was only measured on macOS; Codex's nested sandbox is Landlock/bubblewrap on Linux, so `-s danger-full-access` may or may not be required |
| Probes | the pbcopy probe and the weekly launchd plist are macOS-only; a systemd timer is missing |
| CI | no Linux CI job; the `floor` pytest marker only ran on macOS |
| Install guide | states Linux unsupported; it needs a Linux section once the above is measured |
